# Wireframes: map, incident and emergency

Task P08.02. Editable wireframes for the three mandatory areas - the live
operations map, incident investigation and emergency dispatch - plus the
critical-action confirmation they share, each at the layouts it must work in and
with an accessible alternative where a visual is the primary view.

They are plain SVG: open in Figma, Inkscape or any text editor. They are
generated by `docs/ux/wireframes/build_wireframes.py` so every wireframe shares
the same header, navigation, status shapes and map schematic, and so the
numbered callouts below are single-sourced. Navigation and the signed-in identity
are derived from `source-code/frontend/src/config/inventory.json` - a
wireframe cannot show a role a menu entry the role does not hold. Regenerate
with `python docs/ux/wireframes/build_wireframes.py`;
`python source-code/frontend/tools/verify_wireframes.py` checks the result and
`docs/ux/wireframes/index.html` shows them all in one page.

The palette is the design system's (`design-system/.../MASTER.md`) so contrast is
judged on real colours. These are structure, not final visual design: tokens and
components are fixed in P08.03.

## Layout classes

| Class | Size | Used for | Rules |
|---|---|---|---|
| Laptop (control room) | 1366x768 and up | operators, supervisors, dispatchers, commanders, auditors | full navigation, side panels, all controls; the reference layout |
| Projector (wall display) | 1920x1080 | shared situational display | read-only: no navigation, no controls, larger type, headline indicators, critical incidents only |
| Field | 390x844 | field responders | read-only status, route, ETA and what changed; 44 px minimum touch targets; three-item bottom navigation; **no** approve/request/execute controls |

Between them: at 768-1279 px wide the right-hand panel drops below the main
column and the navigation collapses to a labelled menu button; below 768 px the
field layout applies. At 400% zoom (320 CSS px wide) content reflows to one
column with no two-dimensional page scroll; only the map canvas and wide tables
scroll, each inside its own labelled container. Complex network control stays
desktop-first by design (UX-04).

## Accessible alternatives

| Visual | Equivalent that carries every fact | Notes |
|---|---|---|
| Map canvas | `map-list-laptop`: a real table of the same elements with status, metric, freshness and truth label as columns | one toggle, selection and filters preserved; not a hidden fallback |
| Route on a map | route alternatives as a list with ETA, uncertainty and constraints; turn-by-turn steps on the field view | the map is a preview, never required to act |
| Status colour | a distinct shape plus the word for every state | colour is a hint only |
| Line styles on the map | flowing / slow / closed as solid / dashed / red-with-label plus a legend | the legend is text |
| Live updates | a polite live region with a pause control | focus is never moved by an update |
| Charts (P08.06) | a table view of the same series | see P08.03 chart rules |

## Keyboard and focus order

The first Tab stop on every screen is "Skip to main content". After that, in DOM
order (which matches reading order; nothing uses positive `tabindex`):

| Screen | Order |
|---|---|
| Map | skip link, live-feed status (not a stop), navigation, Map/List toggle, layer checkboxes, map canvas (one stop; arrow keys pan, + and - zoom, Tab to step through selectable elements, Enter selects), legend (not a stop), pause / live / replay slider, selection panel actions, critical incident queue items |
| List | skip link, navigation, Map/List toggle, filters, column headers (Enter or Space sorts), table rows (Enter selects), pause updates, selection panel actions |
| Incident | skip link, navigation, status stepper (only legal next steps are stops), evidence items, hypotheses, linked recommendation and command actions, action bar, note field |
| Dispatch | skip link, navigation, route alternatives (Select), unit status actions, command detail link, timeline |
| Approval dialog | focus enters the dialog on **Cancel** (safe default), Tab cycles inside it, Escape cancels, focus returns to the control that opened it; the page behind is inert |
| Field | skip link, status, route, steps, what changed, bottom navigation |

## Roles and what each wireframe proves

- `operator` sees the incident action bar (it holds `incidents.manage`) and the
  request control on a recommendation (`commands.request`), but no approve
  control: approval belongs to reviewers.
- `dispatcher` sees unit status controls (`emergency.dispatch`) and the
  pre-emption lifecycle, and no "Operations" menu entry (it holds no `ops.view`).
- `supervisor` sees the approval dialog (`commands.review`) and the read-only
  projector view.
- `field_responder` has no control of any kind on the field view.
- The same header shows on every wireframe: a persistent "SIMULATED" tag and
  live-feed state with the age of the newest value.

## What is not wireframed here

Analytics, audit, handover, platform status and demo controls are built from the
same header, navigation, table, chart-with-table and state components; P08.03
specifies those components and their states, and P08.10 tests every screen in
the inventory. They are not separate wireframes because they introduce no new
layout pattern beyond what the three wireframed areas already establish.
